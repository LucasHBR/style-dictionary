# Notes de Lucas
- Un fork est ma copie du dépôt sur GitHub, où j'ai tous les droits.
- Une branche est une ligne de travail parallèle qui ne touche pas à main.
- Un commit est un point de sauvegarde nommé.

## Après questions de Claude 
<b>Fork</b>

créer une copie d'un repository sur lequel on peut travailler librement sans impact sur le repo original

<b>Branche</b>

périmètre de travail parallèle sur lequel on peut avancer, sans impact sur le main du repo, on peut ensuite décider de merge la branche au main, dans ce cas toutes les modifications faites sur la branche seront visibles et appliquées dans le main 

<b>Commit</b>

point de sauvegarde local, sur son ordinateur, qui enregistre les modifications d’un moment précis. L’historique est la suite de tous les commits.

<b>Push</b>

le push transmet les modifications depuis l'ordinateur vers github
